# ナビゲーションの仕様

ホーム、ドロワー、メニュー、ドラッグのあいだをどう行き来するかを定める。
既存のランチャーより使い勝手を高めることが目的であり、そのための原則を先に置き、各操作をその原則に照らして決める。
本書は #11 の作り直し(2026-09-03)を基準にし、#25 のジェスチャ整理(2026-09-05、他のランチャーの調査は docs/06)を反映している。実装と食い違う点があれば本書を直す。

## 原則

ナビゲーションの良し悪しは、機能の数ではなく次の五つで決まる。

1. **指に追従する**。面の出入りは閾値で切り替えず、指の移動量に比例して動く。途中で離せば、その位置と速度から行き先が決まる。
2. **親指の届く場所に置く**。Fold8 のメイン画面は横長 4:3 で、片手で持つと上端に指が届かない。よく使う入口(検索、ドック)は下端に置く。
3. **状態の切り替えを減らす**。ドックはホームに固定し、ドロワーの一部にはしない。重ね描き(フォルダ、メニュー、設定)は同時に一つだけにする。
4. **同じ操作は同じ意味にする**。タップは開く、長押しはつまむ、上スワイプは一覧、下スワイプは検索。場所が変わっても意味を変えない。他のランチャーで広く使われている向きに合わせ、学び直しを要らなくする(#25、docs/06)。
5. **拒否を黙らせない**。置けない、開けない、起動できないときは、その場で分かる反応を返す。落とせないドロップは影が元の位置へ戻り、振動で拒否を伝える(#25)。

## 面の一覧

ランチャーは次の面を持つ。
ホームが土台で、他はその上に重なる。

| 面 | 何を出すか | 入り方 | 出方 |
| --- | --- | --- | --- |
| **ホーム** | ウィジェット面とアプリ面(カバーではめくる、開くと並ぶ)とドック | HOME キー、他の面を閉じる | なし(土台) |
| **ドロワー** | 全アプリと検索欄 | どの面でも上スワイプ(ドック、スクロールしないページ)、縦スクロール面の末尾で上に押す | 下にドラッグ、一覧の先頭で下に引く、Back、HOME キー |
| **検索(Finder)** | 端末の全体検索(Galaxy の Finder / Google)。無ければドロワーを開いて検索欄に焦点 | どの面でも下スワイプ | 検索側で戻る、Back |
| **ウィジェット選択** | 自作ウィジェットと AppWidget の一覧 | ホームメニューの WIDGETS | 外側をタップ、Back、ホームに置く |
| **フォルダ** | フォルダの中身、名前、規則 | フォルダをタップ | 外側をタップ、Back、アプリを起動 |
| **アイテムメニュー** | ショートカット、アプリ情報、サイズ変更、削除 | アイテムを長押しして動かさずに離す | 外側をタップ、項目を選ぶ、Back |
| **ホームメニュー** | ウィジェット追加、設定 | 空き領域を長押し | 外側をタップ、項目を選ぶ、Back |
| **設定** | テーマ選択(今後の設定項目もここ) | ホームメニューから | CLOSE、Back |

ドロワーはアプリ一覧に絞り、ウィジェットの一覧は別の面(ウィジェット選択)に分けた(#25)。
他のランチャーと同じく、日常のアプリ探しとウィジェットの設置を混ぜないためである。
検索は自前で持たず、端末の全体検索(`SearchManager.globalSearchActivity`)へ渡す。Galaxy では Finder が開く。
全体検索が無い端末でだけ、ドロワーを開いて検索欄に焦点を当てる代替に落ちる。

重ね描き(フォルダ、二つのメニュー、設定)は `Overlay` として一つだけ保持し、別の重ね描きに移るときは置き換える。
メニューの項目から別の面に移るときは、その項目がメニューを閉じない。
閉じてしまうと、移った先まで消えるからである(#1 で踏んだ不具合)。

ドロワーは重ね描きではなく、0 から 1 の進捗を持つ独立した層として扱う。
進捗が 0 より大きいあいだだけ合成され、進捗に応じて下から上がる。

## ホームのページ構成

ホームは **ウィジェット面** 1 枚と **アプリのページ** 何枚かで成り立つ(#19、#21、2026-09-04 決定)。
左端にウィジェットの流し読み面、右にめくれるアプリのページという、iOS と同じ並びである。
カバーではこれらを横にめくり、開くとウィジェット面が左、アプリのページが右に並ぶ。
カバーの幅がメインのちょうど半分という Fold8 の形を、そのまま画面の構造にした。

- ウィジェット面には、ウィジェットと大型フォルダを自由に置く。見る領域。縦にいくらでも伸びる。
- アプリのページには、アプリとフォルダを自由に置く。触る領域。先頭のページが HOME の着地。
- アプリのページは段数が固定で、テーマの `grid.rows`(Fold8 は 7)で決まる。段数がそれより少ない画面でだけ縦に流す。
- どちらの面に何を置くかは縛らない。プリセットで誘導するだけにする。
- ページの増減は iOS 式。ドラッグ中に右端へ留めると次のページへめくれ、最後のページなら新しいページができる。空になったページはドラッグが終わると消える(最低 1 枚は残る)。

| 状態 | 見え方 |
| --- | --- |
| カバー(閉) | ウィジェット面、アプリ 1、アプリ 2、… を横にめくる。着地はアプリ 1。ウィジェット面は右へのスワイプ 1 回 |
| メイン横長(開) | 左にウィジェット面(縦スクロール)、右にアプリのページ(横めくり) |
| メイン縦長(開いて回転) | カバーと同じ並びで、余白を広げて置く |

開いたときの左右の境界は、`FoldingFeature` が縦向きのヒンジを返すならその位置と幅に合わせ、返さなければ半分にする。
開いているか閉じているかの判定そのものは幅で足りる(カバー 440〜475dp、メイン 816dp 以上)。ヒンジの情報は境界の補正にだけ使う。

「開いたときだけの内容」は持たない。
開く価値は、ウィジェット面とアプリのページが同時に見えることに置く。

この構造で、ページング(#8)はアプリのページとして実現され、メイン画面のドロワーの形(#9)はアプリ面の続きとして決まる。
並べ替え(#12)はページ内の詰め直しになる。

## ジェスチャの一覧

同じジェスチャはどの面でも同じ意味を持つ。

| ジェスチャ | 場所 | 結果 |
| --- | --- | --- |
| タップ | アプリ | 起動 |
| タップ | フォルダ | フォルダを開く |
| タップ | ショートカット | ショートカットを起動 |
| タップ | ウィジェットの中 | ウィジェット自身が処理(AppWidget のボタン等) |
| タップ | 重ね描きの外側 | 重ね描きを閉じる |
| 長押し(動かさない) | アイテム | アイテムメニュー |
| 長押し(動かさない) | ホームの空き領域 | ホームメニュー |
| 長押し → 移動 | アイテム、ドロワーの項目、メニューのショートカット | ドラッグ開始 |
| 縦スクロール | ホームの各ページ | ページを送る |
| 横にめくる | カバーのホーム、開いたときの右側 | ウィジェット面とアプリの各ページを切り替える |
| ドラッグ中に同じアプリの上に留める(0.5 秒) | グリッド、ドック | 輪が出て、離すとフォルダにまとまる |
| ドラッグ中に端へ留める | ページの左右端 | ページをめくる。最後のページの右端なら新しいページを作る |
| 上にスワイプ | ドック、スクロールしないアプリのページ、縦スクロール面の末尾 | ドロワーを引き上げる(進捗に追従) |
| 下にスワイプ | ドック、スクロールしないアプリのページ、縦スクロール面の先頭 | 検索(Finder)を開く |
| 下にドラッグ | ドロワーの取っ手、一覧の先頭 | ドロワーを引き下げる |
| 縦スクロール | ドロワーの一覧 | 一覧を送る |
| Back | 重ね描きがある | 重ね描きを閉じる |
| Back | ドロワーが開いている | ドロワーを閉じる |
| HOME キー | どこでも | 重ね描きとドロワーをすべて閉じ、アプリの先頭ページに戻る |

## ドロワーの開閉

ドロワーは **進捗** という一つの値(0 = 閉、1 = 開)で動く。
入口は上スワイプに統一した(#25)。ドック、スクロールしないアプリのページ、縦スクロール面の末尾のいずれで上に払っても開く。
ドック右端のドロワーボタンは外した。上スワイプに一本化したことで、専用のボタンが要らなくなったためである。
上にドラッグすると、指の移動量を画面の高さで割った分だけ進捗が増える。
指を離したときの行き先は、まず速度で決め、速度が小さければ位置で決める。

縦方向の払いは、一度の指の動きの中でどちらに決まったかを覚え、決まった向きだけに流す。
上に動き始めたらドロワー、下に引いた量は検索の判定に積む。混ざると、少し上げてから下ろしたときに両方が動いてしまう。
縦スクロールする面では、一覧が消費しきれない端の余りだけを受ける。先頭で下に引けば検索、末尾で上に押せばドロワーになり、スクロールとは競合しない。

- 上向きに 500 px/秒 より速い → 開く
- 下向きに 500 px/秒 より速い → 閉じる
- それ以外 → 進捗が 0.5 を超えていれば開く、超えていなければ閉じる

行き先が決まったら、ばねの動き(跳ね返りなし)で 0 か 1 に落ち着く。

開くあいだ、ホームは奥に引く。
全開で 4% 縮み、透明度は 30% まで下がる。
ドロワーがホームの上に乗っているのではなく、ホームが下がってドロワーが出てくる、という見え方にする。

閉じる操作は三つある。

1. ドロワー上端の取っ手を下にドラッグする。進捗に追従し、離せば同じ規則で行き先が決まる。
2. 一覧を先頭まで戻した状態でさらに下に引く。一覧が消費しきれなかった分をドロワーの進捗に回す。一覧が動けるあいだは一覧が優先されるので、スクロールと閉じる操作が競合しない。
3. Back。

ドロワーからアプリを起動したとき、あるいはドロワーから何かをホームに落としたときは、ドロワーを閉じる。

### 指の移動を取りこぼさない

進捗の更新はアニメーション用の値に非同期で反映するが、指の移動そのものは同期的に積む。
非同期の値から次の値を計算すると、1 フレームに複数回来る移動を取りこぼし、大きく引いても少ししか開かない(作り直しの途中で踏んだ)。
速度は自前で測らず、Compose の `draggable` が返すものを使う。

## ドロワーの中身

上から順に、取っ手、一覧、下端バーの三段にする。

**取っ手** は 28dp の帯で、下にドラッグして閉じるためにある。

**一覧** はアプリのグリッドだけにする(#25)。列数はホームと同じ(カバーと縦長で 6 列、横長で 12 列)。
タブは持たない。ウィジェットの一覧はホームメニューの WIDGETS から別の面で開く。

**下端バー** は検索欄を持つ。
下端に置くのは原則 2 による。
横長のメイン画面では、上端の検索欄は片手で持ったまま打てない。

## 検索

検索には二つある。面全体を探す全体検索と、ドロワーの中でアプリだけを絞る欄である。

**全体検索(Finder)** は、どの面でも下スワイプで開く。
自前では持たず、端末の `SearchManager.globalSearchActivity` に渡す。Galaxy では Finder、素の Android では Google が開く。
アプリだけでなく連絡先や設定、Web まで一度に探せるので、器を用意するより端末のものに乗るほうが良い(docs/06 の調査より)。
全体検索を持たない端末でだけ、ドロワーを開いて下端の検索欄に焦点を当てる代替に落ちる。

**ドロワーの検索欄** はタップで入力状態になる。
入力のたびに一覧が絞り込まれ、先頭に戻る。

絞り込みはアプリ名とパッケージ名を対象にし、次の順位で並べる。

1. アプリ名が入力で始まる
2. アプリ名の単語のどれかが入力で始まる
3. アプリ名が入力を含む
4. パッケージ名が入力を含む

同じ順位の中ではアプリ名の順にする。
先頭一致を上に出すのは、確定キーで先頭を起動したときに狙ったものが出るようにするためである。
確定キーは Go にし、先頭の結果を起動してドロワーを閉じる。
入力があるときは CLEAR を出し、タップで空にする。

タップで入力状態にならない事象が AVD で出ており、実機での確認待ちである(#14)。

## 開くときの動き

開くものは、触った場所から広がる(#23)。
どこを触ったらどれが開いたのかが見えないと、画面が飛んだように感じるためである。

**重ね描き**(フォルダ、二つのメニュー、設定)は、触った要素の矩形を受け取り、その中心を拡大の原点にする。
0.86 倍から等倍へ、透明から不透明へ、220 ミリ秒かけて広がる。閉じるときは 160 ミリ秒で逆に縮む。
閉じる動きを見せるため、状態が空になったあとも終わるまで描き続ける。
拡大の原点を測る矩形は、変形をかける層より外側で測る。内側で測ると、広がる途中で原点が動いてしまう。

**アプリとショートカットの起動** には `ActivityOptions.makeScaleUpAnimation` を渡し、アイコンの矩形から画面が広がるようにする。
あわせて `sourceBounds` も渡す。アプリ側がメニューの位置決めに使うことがある。
矩形が分からないとき(検索の確定キーで起動したときなど)は何も渡さず、システム既定の遷移に任せる。

触った要素の矩形は、タップを扱うジェスチャ処理が位置情報を持っているので、そこからタップの引数として渡す。
描画側が別途座標を測る必要はない。

## 長押しの切り分け

長押しは「つまむ」の意味で統一するが、何をつまむかで行き先が違う。
同じ指の動きなので、取り合いが起きないように判定の順番を決めておく。

**アイテムの上** では、ひとつのジェスチャ処理でタップと長押しを順に判定する。

1. down を受ける
2. 長押しの時間(端末設定、およそ 400〜500 ミリ秒)まで待つ。そのあいだに指が離れればタップ、動きすぎればスクロール等に譲る
3. 長押しが成立したら振動し、ドラッグを始める
4. 離すまでの移動が 12dp 未満ならアイテムメニュー、以上ならドロップ

タップ検出と長押し検出を別々のコルーチンで並べると、片方が最初の down を消費してもう片方に届かず、タップが一度も成立しない(作り直しで見つけた不具合)。
順に判定する形にしてある。

**ホームの空き領域** では、アイテムの長押しより 150 ミリ秒だけ長く待ってから、ドラッグが始まっていないことを確かめてホームメニューを出す。
アイテムの上で長押しすれば、この時点でドラッグが始まっているので、ホームメニューは出ない。
待ち時間で切り分けるのは、Compose のポインタ処理では親と子の両方に同じ長押しが届くためである。

**AppWidget の上** では Compose のポインタ処理が使えないので、ホストビューの派生クラスで長押しを横取りし、画面座標でドラッグ制御に渡す。
横取りしたら親の横取りを禁止し、Compose 側のスワイプ検出に奪われて CANCEL が来るのを防ぐ。

## アイテムメニュー

長押しして動かさずに離すと出る。
アイテムの種類で項目が変わる。

| 種類 | 項目 |
| --- | --- |
| アプリ | そのアプリのショートカット(あれば)、APP INFO、REMOVE |
| フォルダ | OPEN / RENAME、REMOVE |
| 自作ウィジェット、AppWidget | SIZE と W- W+ H- H+、REMOVE |
| ショートカット | LAUNCH、REMOVE |

REMOVE はレイアウト上のアイテムにだけ出す。
ドロワーから開いたメニューには出ない。

ショートカットは Android のアプリショートカット(`LauncherApps.getShortcuts`)で、宣言済み、動的、固定済みのすべてを順位順に並べる。
既定ホームでないときは読めないので、項目自体が出ない。
タップで起動し、長押しドラッグでホームに固定する。
固定するとき、既に固定済みのものと合わせて `pinShortcuts` に渡す(与えた集合で置き換わるため)。

## ホームメニュー

空き領域の長押しで出る。

- WIDGETS: ウィジェット選択を開く
- SETTINGS: 設定画面を開く

どちらも別の面に移るので、メニュー自身は閉じない。
アプリの追加はドロワー(上スワイプ)から長押しドラッグで行うので、ここには置かない(#25)。

## ウィジェット選択

ホームメニューの WIDGETS で開く。
自作ウィジェットと、端末の AppWidget プロバイダを並べる。
それぞれのカードを長押しドラッグしてホームに置く。AppWidget は最小サイズをセル数に切り上げて渡す。
アプリ一覧とは分ける。日常のアプリ探しと、たまにしかしないウィジェットの設置を混ぜないためである(docs/06)。

## ドラッグとドロップ

ドラッグは長押しから始まり、64dp の影が指に追従する。
影はアイコンがあればアイコン、なければ名前を書いた枠にする。

**出発点** は次のどれか。

- ホームのグリッド、ドック、フォルダの中(レイアウト上の位置を持つ)
- ドロワーの APPS、WIDGETS(レイアウト外。落とすと新しく置かれる)
- アイテムメニューのショートカット(レイアウト外。落とすと固定される)

**落とし先** は次のどれか。

- ウィジェット面のグリッド、アプリの各ページのグリッド
- ドック
- 画面上端の削除帯(ドラッグ中だけ出る)

グリッドに落とすときの規則は次のとおり(#25 で押しのけと留めを入れた)。

- 空きセルなら置く。ウィジェットは幅と高さの分だけ空いている必要がある
- 占有セルに落とすと、相手を最も近い空きへ押しのけて割り込む(reflow)。近いものから順に動かし、どれも動かせなければ拒否する
- フォルダにまとめるのは、同じアプリの上に **0.5 秒留めた** ときだけにする。留めると輪が出て、離すとフォルダになる。手動フォルダの上に留めれば中に入る
- 通り過ぎるだけではフォルダにしない。並べ替えの途中でアイコンの上を通っても、勝手にまとまらないようにするため
- 置けないときは拒否し、影が元の位置へ戻って振動する

**落とす位置の事前表示**。ドラッグ中、落ちるセルに枠を出す。何が起きるかで描き分ける。

| 種類 | 見え方 |
| --- | --- |
| 置く(空き) | アクセント色の角丸枠 |
| 押しのけ | アクセント色の角丸枠(内側を薄く塗る) |
| まとめ(留め成立) | アクセント色の輪 |
| 拒否 | 赤い枠 |

ドックにはアプリとフォルダだけ置ける。留めればドックの上でもフォルダにまとまる。
削除帯に落とすとレイアウトから消える。
ドロワーやメニューから来たものを削除帯に落としても何も起きない。
ドラッグ中はホームが削除帯のぶん下がり、先頭の段が帯に隠れないようにする。

**1 個になったフォルダは残す**(#25)。フォルダから最後の 1 個を残して出しても、フォルダの枠は消さない。
中身が 0 になったときだけフォルダを消す。
数が減るたびに枠が出たり消えたりすると、まとめ直すのが面倒になるためである。

ドラッグ中、出発点の重ね描き(ドロワー、フォルダ、メニュー)は見えなくなるが合成には残す。
ジェスチャを続けるためである。
受け付けたら重ね描きを閉じる。拒否されたときは閉じず、続けて置き直せるようにする。

## カバー画面とメイン画面の違い

ジェスチャと面の構造は両画面で同じにし、違いはページの見せ方だけにする。

- カバー: ウィジェット面とアプリの各ページを 1 枚ずつ横にめくる。6 列
- メイン横長: 左にウィジェット面、右にアプリのページ。各 6 列。境界はヒンジの位置
- メイン縦長: カバーと同じ並びで、余白を広げる。6 列
- ドロワーの列数: カバーと縦長で 6、横長で 12
- 検索欄: どれも下端

左右どちらにウィジェット面を置くか(#3)は決めても、ジェスチャと入口の位置は変えない。
